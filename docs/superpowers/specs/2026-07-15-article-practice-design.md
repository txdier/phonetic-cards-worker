# 文章练习与生词联动设计

日期：2026-07-15

## 1. 背景与目标

当前项目是基于 Cloudflare Workers、D1 和原生 HTML/CSS/JavaScript 的单页应用，已经支持登录、个人词本、单词朗读、学习模式和自测模式。

本次功能增加英文文章练习，使用户能够：

- 手动添加并管理英文文章；
- 在手机和电脑上阅读、朗读和恢复阅读进度；
- 在文章中快速标记单词或短语，而不被中文录入打断；
- 稍后在文章内或全局待整理列表中补充中文，并加入现有词本；
- 在所有文章中识别全局待整理项和已加入词本的内容；
- 按文章查看阅读、生词和全文朗读统计。

第一版只处理英文文章，保持联网使用。架构应为以后增加离线同步留出边界，但本次不实现离线模式。

## 2. 范围

### 2.1 第一版包含

- 手动填写标题并粘贴纯文本正文；
- 可选的作者、来源自由文本和备注；
- 按创建时间显示文章列表；
- 添加、编辑和删除文章；
- 文章阅读进度与完成状态；
- 单词和不跨句短语的全局标记；
- 文章内和全局待整理页面的标记管理；
- 待整理项加入词本，并自动带入原文句子作为可编辑例句；
- 原形与词形的手动关联；
- 单词、句子和全文朗读；
- 每篇文章的独立练习统计页面；
- 手机和电脑同等优先的响应式体验。

### 2.2 第一版不包含

- 网页链接抓取、文件导入或富文本导入；
- 自动查询或生成中文释义；
- Markdown、富文本或跨句短语；
- 标签、分类、搜索和筛选；
- 独立的总体统计、趋势图或按天/周统计；
- 完整离线使用和跨设备离线冲突合并；
- 自动词形还原；
- 阅读理解题、文章翻译或自动摘要。

## 3. 已确认的产品规则

### 3.1 导航与页面

应用顶层分为两个平级模块：

1. **记词本**：保留学习模式、自测模式和手动添加单词。
2. **文章练习**：包含文章库、待整理生词和练习统计。

文章阅读页使用专注单栏布局。顶部放置返回、文章信息、全文朗读控制、语速和编辑入口。正文保持适合阅读的行宽，手机和电脑使用相同的信息层级。

### 3.2 文章

文章字段包括：

- 标题，必填；
- 纯文本正文，必填，保留段落和换行；
- 作者，可选；
- 来源，可选，是一个可填写名称或网址的自由文本字段；
- 备注，可选；
- 创建时间和更新时间。

文章通常少于 1,000 个英文单词。文章库第一版只按创建时间浏览。

编辑正文时，保存前询问用户是保留还是重置阅读进度和统计。删除文章前需要确认。

### 3.3 生词标记

- 标记与加入词本是两个阶段。
- 用户通过浏览器文本选择来选中一个单词或短语，再使用附近的浮动操作条标记或朗读。
- 短语可以包含任意数量的英文单词，但不得跨句。
- 标记在用户范围内全局共享，匹配忽略大小写并折叠连续空格。
- 自动同步到其他文章的高亮不会自动成为该文章的主动标记来源。
- 用户可以在自动高亮所在文章中再次选择并确认标记，使该文章成为主动来源。
- 尚未加入词本的标记可以在文章阅读页或全局待整理页面取消。
- 文章阅读页的“取消本篇标记”只删除当前文章的主动来源；全局待整理页面的“取消”一次删除该待整理项的全部主动来源，并彻底移除全局标记。

删除文章或编辑掉某个主动标记的全部出现位置时，删除该文章的主动来源关系。只有在该待整理项不存在其他主动来源时，才删除其全局标记。其他文章中的自动出现不算主动来源。

### 3.4 加入词本与词形

- 加入词本时必须手动填写中文释义。
- 例句默认使用首次主动标记时的原文句子，允许修改。
- 原形由用户手动填写；系统不自动猜测。
- 词卡以原形为主词，并同时展示已记录的具体词形。
- 主词和所有词形共享中文释义、例句和熟悉度，并都能在文章中匹配。
- 遇到相同原形的既有词卡时，提示用户选择合并或新建。
- 如果同一原形存在多张词卡，文章查询卡显示全部匹配释义。
- 加入词本后，文章中的匹配内容继续高亮，但切换为“已加入词本”样式。
- 删除词卡时，同时删除它的词形、全局识别和相关主动标记来源；文章中的对应内容恢复普通文本。

### 3.5 朗读

- 使用浏览器 Web Speech API，优先选择美式英语语音；没有美式语音时回退到其他英文语音。
- 点击词本内容可查看中文释义和发音。
- 普通选择浮层提供所选单词或短语的朗读。
- 点击句子可以朗读整句。
- 全文朗读按句播放，支持播放、暂停、继续、从任意句子开始、当前句高亮和语速调节。
- 语速使用 `0.5×–1.5×` 滑块，步进为 `0.5×`。
- 一次朗读到达文章末尾，且本次实际覆盖至少 80% 的句子，才增加一次完整全文朗读次数。

### 3.6 阅读进度与统计

- 打开文章后恢复上次阅读位置。
- 只有从正文顶部开始并到达末尾，才自动标记完成并增加一次阅读次数。
- 页面处于前台，且最近 1 分钟内发生过滚动、选词、点击或朗读操作时，才累计有效阅读时长。
- 阅读位置和时间增量定期保存，并在页面隐藏或离开文章时再保存一次。
- 统计页面按文章逐项显示，不提供总体合计或趋势图。

每篇文章显示：

- 完整阅读次数；
- 累计有效阅读时长；
- 主动标记总数；
- 当前待整理数；
- 已加入词本数；
- 完整全文朗读次数。

主动标记统计不包含从其他文章自动同步而来、但未在本文确认过的高亮。

## 4. 技术方案

### 4.1 选定方案

正文以纯文本作为唯一持久化内容。打开阅读页时，前端动态分段、分句，并根据全局待整理项和词本词形生成交互式正文。

不持久化每次出现的字符位置，也不在保存文章时生成完整词元表。单独持久化“用户在哪篇文章中主动标记过哪个内容”的来源关系。

选择该方案的原因：

- 符合现有原生前端架构；
- 文章短，动态解析的性能成本可控；
- 编辑正文不会导致大量字符位置失效；
- 可以准确实现“自动高亮不算主动来源”的规则；
- 数据模型比预生成词元或逐次位置标注更简单。

### 4.2 前端模块边界

现有前端集中在 `public/index.html`。实施时按功能拆分，避免文章功能继续扩大单文件：

- 应用入口与登录状态；
- 顶层导航与轻量路由；
- API 客户端；
- 记词本学习与自测；
- 文章库与文章表单；
- 阅读器；
- 文本分句、匹配和渲染；
- 待整理生词；
- 练习统计；
- 语音播放服务；
- 阅读会话和有效时间跟踪。

拆分只服务本功能，不进行无关的视觉重写或后端重构。

### 4.3 后端职责

Worker 继续负责登录校验、用户隔离、输入验证和 D1 访问。新增接口按以下资源组织：

- 文章列表、创建、读取、编辑和删除；
- 全局待整理项列表；
- 创建或取消文章主动标记；
- 将待整理项加入新词卡或合并到已有词卡；
- 阅读进度和统计增量；
- 统计页的逐文章汇总。

所有资源读取和修改都必须同时使用资源 ID 与当前 `user_id` 约束。

## 5. 数据模型

实施时创建新的迁移文件，不修改已经存在的迁移。

### 5.1 `articles`

- `id`
- `user_id`
- `title`
- `body`
- `author`
- `source`
- `notes`
- `created_at`
- `updated_at`

### 5.2 `article_progress`

每个用户、每篇文章一条：

- `article_id`
- `user_id`
- `last_position_ratio`
- `completed`
- `read_count`
- `active_read_ms`
- `full_read_aloud_count`
- `updated_at`

统计增量需要携带客户端生成的操作或会话标识，后端据此避免网络重试造成重复计数。

### 5.3 `marked_terms`

保存当前全局待整理项：

- `id`
- `user_id`
- `display_text`
- `normalized_text`
- `kind`，取 `word` 或 `phrase`
- `created_at`

同一用户的 `normalized_text` 唯一。

### 5.4 `article_markings`

保存主动来源及其上下文：

- `id`
- `article_id`
- `user_id`
- `normalized_text`
- `selected_text`
- `context_sentence`
- `marked_term_id`，待整理状态时使用；
- `word_id`，加入词本后使用；
- `created_at`

同一文章和同一归一化文本只保留一条主动来源记录。待整理项加入词本时，来源记录从 `marked_term_id` 转为 `word_id`，因此文章统计仍能区分待整理和已加入状态。

### 5.5 词卡与词形

扩展现有 `words` 表，使主英文内容代表原形。现有数据的原形默认等于当前 `en`。新增词形表保存：

- `id`
- `word_id`
- `user_id`
- `form`
- `normalized_form`
- `created_at`

同一词卡内的归一化词形唯一。允许同一用户创建多个相同原形的词卡，以支持不同释义；查询时返回全部匹配卡片。

### 5.6 `article_progress_events`

保存用于统计去重的增量操作：

- `id`，使用客户端生成的唯一操作标识；
- `article_id`
- `user_id`
- `event_type`，取有效阅读时长增量、完整阅读或完整全文朗读；
- `amount`，时长事件保存毫秒数，计数事件保存 `1`；
- `created_at`

后端先写入唯一事件，再更新 `article_progress`。相同事件重复提交时不再次累计。实现可定期清理超过保留窗口的旧事件，但清理规则不能影响仍可能重试的近期操作。

## 6. 阅读器解析和匹配

1. 将纯文本正文按段落保留。
2. 使用浏览器的句子分段能力划分句子；在缺少该能力时使用可测试的英文回退规则。
3. 获取当前用户的待整理项、词卡主词和词形。
4. 对匹配项按单词数量和字符长度降序排列，优先匹配最长短语。
5. 匹配必须尊重英文单词边界，不能把 `art` 匹配进 `article`。
6. 已匹配的范围不再被较短项目重复覆盖。
7. 词本匹配使用“已加入词本”样式；待整理匹配使用“待整理”样式。
8. 同一文本同时命中待整理项和词卡时，以词卡状态为准。

用户选择文本时：

- 去除两端空白和标点；
- 折叠内部连续空格；
- 至少包含一个英文字母；
- 起止位置必须落在同一句内；
- 不符合规则时不显示标记操作，并提供简短原因。

## 7. 主要数据流

### 7.1 标记

1. 用户选择文本并点击“标记生词”。
2. 前端提交文章、归一化文本、显示文本和当前句子。
3. 后端幂等创建或复用全局待整理项。
4. 后端幂等创建当前文章的主动来源。
5. 前端重新应用全局高亮。

如果全局待整理项已经由其他文章创建，只新增当前文章的主动来源。

### 7.2 加入词本

1. 用户从阅读页或待整理页打开加入表单。
2. 表单预填选中文本、原文句子，并要求填写中文。
3. 用户可填写原形；不填写时原形等于选中文本。
4. 后端发现相同原形时返回已有词卡摘要。
5. 用户选择合并或新建。
6. 新建或更新词卡和词形。
7. 所有相关主动来源由待整理状态转为该词卡。
8. 全局待整理项删除，文章中的匹配样式切换为词本状态。

### 7.3 取消标记

文章内取消：

1. 删除当前文章的主动来源。
2. 若该项仍有其他主动来源，保留全局待整理项。
3. 若没有其他主动来源且尚未加入词本，删除全局待整理项。

全局待整理页面取消：删除该待整理项的全部主动来源，然后删除全局待整理项。

### 7.4 删除或编辑文章

删除文章时，先清理它的主动来源，再按取消标记规则清理失去最后来源的待整理项，最后删除进度和文章。

编辑正文时，比较现有主动来源是否仍在新正文中完整出现。不存在的来源按取消标记规则清理。保存前由用户选择保留或重置进度与统计；选择保留时位置比例被限制在有效范围内。

### 7.5 阅读会话

- 页面位于前台且最近一次有效交互不超过 1 分钟时累计时间；
- 有效交互包括滚动、选词、点击和朗读控制；
- 阅读会话只有先到达顶部再到达末尾，才提交一次完整阅读事件；
- 全文朗读按句记录本次已完成的句子，只有到达末尾且覆盖率至少 80% 才提交一次完成事件；
- 完成事件使用唯一标识，重复提交不会重复计数；
- 时间与位置采用增量和最新值保存，在页面隐藏、离开和固定间隔触发。

## 8. 错误处理

- 前后端同时验证标题、正文、中文释义和资源所有权。
- 保存失败时保留表单内容并显示页内错误。
- 快速标记和取消可以乐观更新；接口失败时恢复原状态。
- 相同原形冲突必须由用户选择合并或新建，后端不能自行决定。
- 关联数据修改必须保持整体一致，避免半完成状态。
- 阅读进度或统计保存失败时暂存在浏览器并自动重试；该队列与将来的离线同步层隔离。
- 语音 API 不可用时禁用朗读控制并说明原因。
- 美式语音不可用时回退到其他英文语音。
- 朗读被取消、中断、报错、未到末尾或覆盖不足 80% 时不增加计数。
- 接口对无效输入返回明确的 4xx 错误，对未授权访问返回 401，对不属于当前用户的资源按不可访问处理。

## 9. 测试策略

### 9.1 单元测试

- 大小写和空格归一；
- 英文边界和标点处理；
- 句子划分及回退规则；
- 单词与短语最长匹配；
- 跨句选择拒绝；
- 有效阅读时间和 1 分钟空闲暂停；
- 顶部到末尾阅读判定；
- 全文朗读 80% 覆盖判定。

### 9.2 API 与数据测试

- 未登录访问和用户数据隔离；
- 文章的增删改查；
- 重复标记的幂等性；
- 跨文章自动显示与主动来源隔离；
- 取消标记及最后来源清理；
- 删除文章和编辑正文后的清理；
- 待整理项加入新词卡或合并词卡；
- 相同原形新建多张词卡；
- 删除词卡后的词形和来源清理；
- 进度、阅读次数和朗读次数的重复请求去重。

### 9.3 界面与回归测试

- 手机和电脑的文章列表与单栏阅读布局；
- 选择浮层、待整理高亮和词本高亮；
- 多释义查询卡；
- 文章内和全局待整理流程；
- 编辑文章时保留或重置统计；
- 句子朗读和全文朗读控制；
- 当前词本添加、删除、朗读、熟悉度和自测功能不回归。

## 10. 验收标准

1. 用户可以手动创建一篇英文纯文本文章并在手机或电脑上阅读。
2. 用户可以选择单句内的单词或短语进行全局标记，阅读过程不要求立即填写中文。
3. 标记在其他文章中自动高亮，但只有主动确认过的文章计为来源。
4. 用户可以在阅读页或待整理页填写中文并加入词本，例句自动取自原文且可修改。
5. 原形和词形能够共同匹配文章；相同原形支持用户选择合并或新建。
6. 已加入词本的内容使用独立样式，点击可查看一个或多个中文释义并发音。
7. 删除文章、编辑正文、取消标记和删除词卡时，标记状态按已确认规则一致更新。
8. 单词、句子和全文朗读可用；全文朗读支持暂停、继续、任意句开始、当前句高亮和语速调节。
9. 只有到达末尾且覆盖至少 80% 的全文朗读增加统计。
10. 只有从顶部阅读到末尾增加阅读次数；无操作 1 分钟后停止累计有效时长。
11. 独立统计页能按文章显示所有已确认指标。
12. 现有记词本学习和自测功能继续正常工作。
