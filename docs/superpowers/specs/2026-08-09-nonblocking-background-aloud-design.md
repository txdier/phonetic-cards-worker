# 非阻塞后台朗读回归修复设计

## 背景与目标

现有 iOS HLS 后台朗读会在全文播放开始前准备整篇音频，并把播放器切换到 `loading`。这使“开始朗读”和从保存点“继续”长时间停留在“正在准备后台朗读”。浮动控制区仅在 `idle`、`paused`、`speaking` 状态显示，因此准备期间会消失；当前句位置尚未建立时，“上一句”和“重听”也无法工作。

本次修复把后台朗读降级为普通朗读的增强能力，而不是播放前置条件。点击开始或继续后应立即播放逐句音频；HLS 在后台准备，准备成功后才在安全的句子边界接管。后台准备不得阻塞普通朗读、改变用户可见进度，或使浮动控制失效。

## 播放架构

全文朗读继续使用一个文章会话维护开始位置、当前句、已完成句和播放意图。会话启动时立即调用现有逐句播放路径，让首句的获取与播放保持原有行为。同时启动可取消的 HLS 准备任务，但该任务不拥有播放器状态，也不发布替代普通播放状态的全局 `loading`。

HLS 准备结果保存在当前文章会话内。准备完成时，如果普通逐句音频仍在播放，则等待当前句自然结束，再从下一句的开头切换到 HLS；如果会话已暂停，则保留结果，直到用户继续；如果用户已切句，则以切句后的可听位置为准，不使用过期的接管位置。会话停止、文章切换或新的全文朗读开始时，中止旧准备任务并丢弃其结果。

HLS 准备失败、超时、返回无效时间线或媒体播放失败时，继续使用逐句朗读。失败不应将正常播放改为暂停，也不应反复显示准备状态。

## 控制区行为

浮动控制区以实际可听播放状态为准，在后台准备期间保持显示。

- 中间按钮在有声音时显示“暂停”，点击后暂停并保留当前位置；暂停时显示“继续”，点击后恢复。
- “上一句”和“重听”始终针对实际当前句。后台准备任务不能清空当前句，也不能让按钮因准备状态而失效。
- 用户暂停时，已完成的 HLS 准备结果不得自动开始播放；只有再次继续后才能接管。
- 用户切到上一句或重听时，普通逐句播放立即响应；后续 HLS 接管重新依据最新实际位置计算。

界面可以提示后台能力正在准备或已回退，但提示不得覆盖正常的“开始朗读”“继续全文朗读”“已暂停”等主要状态，也不得造成看似卡住的体验。

## 进度与完成度

后台音频的生成和准备不计入朗读进度。只有实际播放完成的句子才进入完成集合。

从逐句播放切换到 HLS 时，当前已经完成的句子沿用原集合；HLS 从下一句开头接管，避免重复播放或重复计数。暂停点始终来自实际可听媒体的位置。切句或重听后的覆盖率沿用现有规则，不因 HLS 时间线已生成而提前增长。

## 错误与竞态处理

HLS 准备任务绑定文章会话和生成令牌。所有异步结果在写入会话前检查令牌与会话身份，过期结果直接忽略。暂停只改变播放意图，不销毁已经安全完成的准备结果；停止或重新开始则中止旧任务。

接管时若 `play()` 被浏览器拒绝，播放器保留当前位置并回到可继续的暂停状态。其他 HLS 媒体错误回退到逐句模式，从当前可听句和偏移继续，不能从头开始。

## 测试范围

播放器测试覆盖以下行为：

- 原生 HLS 可用时，文章首句仍立即走逐句音频，HLS 准备并行进行。
- HLS 准备完成后只在句子边界接管，并从正确的下一句开始。
- 准备期间暂停、继续、上一句和重听立即生效。
- 暂停期间准备完成不会自行播放。
- HLS 准备失败、无效或接管失败时继续逐句播放。
- 逐句与 HLS 交接前后完成集合、覆盖率和暂停点不重复、不跳跃。
- 新会话或停止操作会使旧准备结果失效。

阅读器 DOM 测试覆盖浮动控制区在后台准备相关状态下保持可见，主按钮反映实际播放状态，上一句和重听仍调用播放器控制，并且普通朗读状态提示不被“正在准备后台朗读”长期占用。
