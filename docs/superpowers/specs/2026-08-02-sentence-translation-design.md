# 单句翻译与持久缓存设计

## 目标

在文章阅读页增加可选的“逐句翻译”模式。用户可在每个英文句子下方直接触发翻译，译文在原位显示，并尽量避免翻译完成后引起页面跳动。

单句翻译必须结合句子所在的完整自然段理解上下文。同一用户、同一原句、同一自然段上下文、同一模型及同一翻译规则版本的结果应被复用，重复查看或点击不能再次消耗 Workers AI 额度。

## 非目标

- 不改变现有的点击英文句子立即朗读行为。
- 不把自然段全文译文自动拆分为单句译文。
- 不把多个单句译文拼接为全文译文。
- 不在不同用户之间共享私人文章的译文缓存。
- 不缓存 `/api/*` 请求到 PWA Service Worker 或浏览器 HTTP 缓存。

## 阅读器交互

### 逐句翻译模式

阅读工具栏增加“逐句翻译”开关，并在本地记忆用户偏好。普通阅读模式保持当前紧凑排版；开启逐句翻译模式时，阅读器一次性为文章中的每个句子建立独立译文槽。

英文句子和译文槽职责分离：

- 点击或键盘激活英文句子仍然朗读该句。
- 点击或键盘激活译文槽才触发单句翻译。
- 译文槽的移动端最小触控高度为 44px。
- 常见译文预留两行高度；译文超过预留高度时允许自然增长，不截断内容。

开启模式会产生一次明确且可预期的布局变化。建立槽位后，未翻译、加载中、成功和失败状态使用相同的最小高度，因此普通翻译响应不会再次推动后续正文。

### 译文槽状态

译文槽具有四种状态：

1. `idle`：显示低对比度“译”图标和“翻译本句”提示。
2. `loading`：保持槽位高度，显示加载状态并禁止重复提交。
3. `translated`：原位显示完整中文译文，并提供次要的“重新翻译”按钮。
4. `error`：原位显示简短错误和“重试”操作，不影响其他句子。

状态变化通过适当的 `aria-live` 或 `role="status"`/`role="alert"` 通知辅助技术。操作元素必须可通过 Tab 聚焦，并支持 Enter 和 Space。

“重新翻译”显式绕过当前缓存并更新对应缓存记录，因此会消耗一次 Workers AI 调用。界面在用户操作前不自动刷新有效缓存。

## 与全文翻译的关系

“逐句翻译”和“显示全文译文”是互斥的显示模式：

- 开启逐句翻译时隐藏标题及自然段全文译文，显示所有单句槽。
- 显示全文译文时关闭逐句显示，隐藏所有单句槽。
- 切换显示模式不删除任何缓存；返回逐句模式时立即恢复已有单句译文。
- “翻译全文”生成的仍是自然段级连贯译文，不填充单句缓存。
- 单句翻译始终独立生成，不用于拼接或覆盖全文译文。

若用户尚未生成全文译文，“显示全文译文”维持现有不可用或隐藏状态。生成全文译文后切换到全文显示属于用户明确触发的布局变化，不受单句槽稳定性要求限制。

## 上下文与缓存身份

服务端是原句和上下文的唯一可信来源。前端只提交文章内的全局句子索引及当前原句校验哈希；服务端重新读取用户拥有的文章，使用与阅读器一致的自然段和句子切分规则定位：

- 要翻译的完整英文句子；
- 该句所在的完整自然段。

模型提示固定注入现有六条翻译规则，并明确要求结合完整自然段理解语境、只返回目标句子的简体中文译文。

缓存身份包含：

```text
user_id + normalized_sentence + normalized_paragraph + model + rules_version
```

最终缓存键使用上述字段的稳定序列化结果计算 SHA-256。文章标题不参与单句模型提示或缓存身份；完整自然段是单句翻译的全部消歧上下文。

缓存按用户隔离。完全相同的句子如果位于不同自然段上下文中，需要分别翻译；同一上下文在同一用户的不同文章中可以复用。

## 数据模型

新增 `sentence_translation_cache` 表：

| 字段 | 用途 |
| --- | --- |
| `user_id` | 缓存所有者，与认证用户隔离 |
| `cache_key` | 上下文感知的 SHA-256 缓存键 |
| `source_hash` | 前端恢复和源文本校验 |
| `context_hash` | 自然段变化校验 |
| `sentence_text` | 生成译文时的标准化原句 |
| `translation_zh` | 中文译文 |
| `model` | Workers AI 模型标识 |
| `rules_version` | 翻译规则版本 |
| `created_at` | 首次生成时间 |
| `updated_at` | 最近生成或显式刷新时间 |

主键为 `(user_id, cache_key)`。不使用 `article_id` 作为缓存身份，因此相同上下文可跨该用户自己的文章复用。文章删除时不删除缓存；文章内容变化后，新计算的键自然不会命中旧结果。

缓存表不建立原文到其他用户的可查询索引，所有读取和写入都必须绑定当前认证 `user_id`。

## API

### 批量读取已有单句译文

```http
GET /api/articles/:id/sentence-translations
```

服务端验证文章所有权，重新切分当前正文，批量查询可命中的缓存，并返回：

```json
{
  "sentences": [
    {
      "sentenceIndex": 3,
      "sourceHash": "...",
      "translation": "……"
    }
  ]
}
```

仅返回已有缓存的句子；未翻译句子不需要产生空记录。

### 翻译或读取一个句子

```http
POST /api/articles/:id/sentence-translations
Content-Type: application/json

{
  "sentenceIndex": 3,
  "sourceHash": "...",
  "refresh": false
}
```

处理顺序：

1. 验证认证、文章所有权、索引类型和输入长度。
2. 从当前文章重新定位句子和完整自然段。
3. 校验 `sourceHash`，不一致时返回源文本已变化错误。
4. 计算上下文感知缓存键。
5. `refresh` 不为 `true` 时先查询缓存；命中即直接返回。
6. 未命中或显式刷新时调用 Workers AI。
7. 严格校验模型只返回译文结构后，以唯一约束写入或更新缓存。
8. 返回：

```json
{
  "sentenceIndex": 3,
  "sourceHash": "...",
  "translation": "……",
  "cached": true
}
```

`cached` 表示本次响应是否完全来自已有缓存。显式刷新成功时为 `false`。

## 并发与一致性

前端为每个句子维护独立请求代次：

- 同一句加载时禁用其翻译和刷新操作。
- 不同句子可以独立翻译，某句失败不会覆盖其他句子的状态。
- 页面卸载、文章切换或较新的同句请求出现后，旧响应不得更新 DOM。

D1 的 `(user_id, cache_key)` 唯一约束负责最终去重。两个极短时间内同时发生的缓存未命中仍可能各自调用模型；正常 UI 会阻止同一页面中的这种重复请求。此设计不引入 Durable Object，仅为消除罕见并发模型调用而增加全局协调不符合当前范围。

写缓存前服务端再次确认文章拥有者及当前源文本。如果文章在模型推理期间发生变化，返回 `TRANSLATION_SOURCE_CHANGED`，不得保存与旧文本关联的新结果。

## 错误处理

沿用现有翻译错误格式和稳定错误码，包括输入无效、文本过长、额度耗尽、模型不可用、超时、返回格式异常及源文本变化。

- 缓存读取失败时不伪装成缓存未命中，返回可重试错误，避免不必要地消耗 AI 额度。
- 模型调用失败时不写入缓存，并保留页面上已有译文。
- 显式刷新失败时继续显示旧译文，同时在槽内提供非破坏性的重试提示。
- 离线时不调用 API，槽内显示需要联网的提示；PWA Service Worker 继续对所有 `/api/*` 请求采用 network-only。
- 批量恢复失败不阻止文章正文和朗读功能。

## 测试与验收

### 服务端

- 相同用户、句子、自然段、模型和规则版本命中缓存时不调用 AI。
- 自然段、模型或规则版本任一变化都会缓存未命中。
- 相同上下文可跨同一用户的文章复用，但不同用户不能互相读取。
- 服务端使用完整自然段作为上下文，只要求返回目标句译文。
- 伪造索引、过期 `sourceHash`、越权文章和超长输入在 AI 调用前被拒绝。
- 模型解释、额外字段、空译文、额度错误和超时不会产生缓存记录。
- 推理期间文章变化不保存结果。
- 显式刷新成功更新缓存，失败保留旧缓存。

### 前端

- 普通模式保持现有文章排版。
- 开启逐句模式时一次性创建全部译文槽；译文响应前后常规槽位高度稳定。
- 点击英文句子继续朗读，点击译文槽只翻译。
- 页面加载时恢复已有译文，不自动翻译未缓存句子。
- 每句的加载、成功、失败和重试状态互不干扰。
- 旧响应不能覆盖文章切换后的页面或同句较新响应。
- 逐句模式与全文译文互斥显示，往返切换不丢失任何结果。
- 键盘、焦点、状态通知和 44px 触控区域符合现有无障碍约束。
- 离线和 API 失败不被误报为登录失效。

### 手工验收

- 在 Android Chrome 和 iPhone Safari 检查逐句模式、滚动稳定性、触控目标和长译文扩展。
- 验证同一句重复点击、刷新页面及同上下文跨文章访问不会产生新的 AI 调用。
- 验证自然段上下文变化后会重新翻译。
- 验证全文译文与逐句译文切换没有重复中文或残留控件。
