# 关系弹窗与阅读进度请求优化设计

## 目标

在不改变现有关系 API、关系交互流程和阅读统计语义的前提下，完成三项优化：

- 重整词间关系弹窗的视觉层级，并统一同级按钮高度。
- 让词卡右上角的编辑和更多操作按钮贴合卡片顶部及右侧边缘。
- 避免阅读器周期性提交内容完全相同的进度快照。

## 当前问题与根因

### 关系弹窗

当前添加关系表单直接使用两列网格。按钮与带标签的表单字段处于同一网格行时，会被网格默认的拉伸行为撑到整行高度，因此“搜索”和“添加关系”按钮高度不同于输入框，也缺少清晰的表单分组。已有关系和添加关系之间仅靠标题与间距区分，信息层级偏弱。

### 词卡操作区

词卡使用 `16px` 内边距，操作区位于普通标题网格内，因此两个按钮虽然尺寸一致，但仍与卡片顶部、右侧边缘保持内缩距离。

### 阅读进度请求

阅读器每 15 秒执行一次 `saveProgress()`。该函数会无条件提交一个 position 项，即使 `lastPositionRatio` 和 `lastAloudSentenceIndex` 与上一次入队值完全一致。标签页显隐、阅读器卸载和朗读状态变化还会触发额外保存，导致同一 `/api/articles/:id/progress` 地址持续收到重复 PATCH 请求。

## 关系弹窗设计

弹窗继续使用居中模态框，不改为抽屉。内容拆成两个有独立表面、边框和内边距的区块：

1. “已有关系”：空状态显示在轻量提示区域；存在关系时，每条关系以清晰的内容列和删除操作列呈现。
2. “添加关系”：表单按以下结构排列。

```text
搜索关联词
[搜索输入框                         ][搜索]

[关联词选择                       ][关系类型]

[备注（可选）                              ]

                              [添加关系]
```

桌面端规则：

- 搜索输入框和搜索按钮处于同一个控件行。
- 关联词与关系类型各占一列，列宽相等且允许收缩。
- 备注独占整行。
- 主操作位于独立表单底部，右对齐。
- 输入框、选择框、搜索按钮、添加按钮和关闭按钮的交互高度统一为 `44px`。
- 搜索按钮使用固定的次要操作宽度，添加按钮使用适合文案的固定最小宽度；统一的是高度和视觉重量，不强制不同文案按钮等宽。
- 关系删除按钮使用统一的紧凑危险操作规格，不与主操作争夺视觉层级。

移动端规则：

- 弹窗保持接近全宽、限制最大高度并内部滚动。
- 搜索控件行、两个选择框和表单底部操作在窄屏下改为单列。
- 主按钮在窄屏下占满可用宽度。
- 不产生横向滚动。

所有现有加载、错误重试、搜索、新增、删除、Escape、焦点循环和焦点返回行为保持不变。

## 词卡操作区设计

- `.pc-card-top-actions` 从标题网格中的普通定位改为相对词卡绝对定位：`top: 0; right: 0`。
- 两个按钮仍为 `44×44px`，间距保持 `8px`，操作区总宽仍为 `96px`。
- 更多按钮的右上圆角与词卡圆角协调，使按钮命中区域贴边但不破坏卡片轮廓。
- 标题内容继续保留 `96px` 操作空间，长单词和短句不会进入按钮下方。
- 菜单继续相对于操作区向下、向左展开，键盘与焦点行为不变。

## 阅读进度去重设计

阅读器内部记录最近一次已入队的位置快照，快照由以下字段组成：

- 当前文章 ID；
- 当前滚动比例；
- 当前朗读断点索引，包括 `null`。

`saveProgress()` 仍按原频率执行，并继续刷新活跃阅读时长事件。生成 position 快照后：

- 若快照与最近一次入队快照完全一致，不再调用 `progressQueue.submit()`；
- 若任一字段变化，则提交新的 position 项并更新最近快照；
- 首次可保存时必须提交；
- 阅读器卸载、标签页显隐或朗读状态变化触发保存时，同样遵守去重规则；
- 事件类进度（阅读完成、朗读完成、活跃毫秒数）不参与此去重，保持原有可靠队列语义；
- 请求失败后的 position 项仍由现有持久化队列保存，并在现有重试触发点继续发送。

滚动比例不做粗粒度取整或阈值过滤，以免改变现有进度精度；本次只消除内容完全相同的重复请求。

## 实施边界

- 修改 `public/styles.css` 和必要的 `public/words-view.js` 弹窗结构类名。
- 修改 `public/reader-view.js` 的 position 快照去重逻辑。
- 不修改后端接口、数据库、队列存储格式或统计口径。
- 不修改关系字段、文案和业务动作。
- 不进行与本次视觉及请求问题无关的重构。

## 测试与验证

按测试驱动方式补充回归约束：

- 关系弹窗具有独立区块和搜索控件行。
- 表单主要控件高度统一为 `44px`，删除操作具有独立紧凑规格。
- 桌面端表单层级和移动端单列规则存在，且不会横向溢出。
- 卡片操作区使用 `top: 0; right: 0`，按钮尺寸、间距和标题预留宽度保持正确。
- 首次定时保存会提交 position。
- 未改变位置及朗读断点时，多次定时保存只提交一次 position。
- 位置或朗读断点变化后会再次提交 position。
- 相同快照下活跃时长事件仍正常提交。
- 标签页显隐和卸载不会为相同快照增加重复 position 项。

最后运行相关 DOM/CSS 测试、完整 `npm.cmd test`、JavaScript 语法检查和差异检查。
