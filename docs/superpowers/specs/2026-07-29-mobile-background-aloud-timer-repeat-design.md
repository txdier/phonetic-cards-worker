# 移动端后台朗读、倒计时与单句重听设计

## 背景

文章阅读器已经支持 Azure TTS、浏览器语音降级、全文逐句朗读、暂停继续、语速调整、当前句跟随和句级跨设备断点。当前移动端仍有三个问题：

1. 全文朗读为每个句子创建新的 `Audio` 对象和 Blob URL。手机锁屏后，浏览器可能在句间冻结 JavaScript，导致下一句不能继续。
2. 锁屏或页面被系统回收后，现有进度只依靠异步网络请求保存句号，可能丢失当前句，且不能恢复句内秒数。
3. 没有定时暂停功能；手机端也缺少不干扰原生文字选择的“上一句”和“本句”快捷回听入口。用户常在下一句已经开始后，才发现刚听完的上一句没有听清，因此两个目标不能合并为一个由系统猜测的“重听”操作。

目标平台同时包括 iPhone Safari 与 Android Chrome。

## 目标

- 在支持后台媒体播放的手机浏览器中，锁屏后尽可能连续朗读全文。
- 亮屏、刷新或页面被系统回收后，保留当前句及句内播放位置。
- 提供朗读倒计时，到点时立即暂停，即使当前句尚未读完。
- 提供移动端易触达的“上一句”和“本句”，回听完成后自动继续后文。
- 支持系统锁屏媒体控制时，尽可能提供播放、暂停、上一句、本句和下一句。
- 保留现有 Azure TTS、R2 逐句缓存、Web Speech 降级、语速、单句点读和朗读完成统计。

## 浏览器能力边界

移动网页不能像原生 App 一样保证后台 JavaScript 在指定时刻被操作系统唤醒。设计通过长期存活的 HTML 媒体元素、Media Session、音频事件和绝对截止时间提高后台可靠性，但不承诺原生 App 级别的后台调度。

如果锁屏期间操作系统彻底冻结网页，倒计时应在浏览器下一次调度或页面重新可见时立即补做暂停。该边界必须在真实设备验收中明确验证和记录。

## 播放架构

### 单一 HTML 音频元素

`createTtsPlayer` 在整个应用生命周期中只创建并复用一个 `HTMLAudioElement`。全文朗读换句时只更新同一元素的音频源，不创建新的播放器实例。

播放器维护统一快照：

- 播放模式：空闲、全文播放、全文暂停或单次点读；
- 文章 ID；
- 当前句索引；
- 当前句内秒数与音频时长；
- 语速；
- 全文起始句与完成覆盖率；
- 当前操作是否为“上一句”或“本句”回听。

播放器继续逐句请求现有 `/api/tts/articles/:articleId/sentences/:index` 端点。Azure 与 R2 仍以句子为缓存单位，不新增整篇或分块音频。

“当前句”严格定义为最近实际开始发声的句子。预加载、设置下一句 URL 或等待缓冲不得提前改变当前句。当前句尚未结束时，“本句”回听当前句；当前句已经结束但下一句尚未发声时，当前句仍是刚结束的句子；下一句开始发声后，下一句才成为当前句。

换句、暂停、恢复、上一句、本句、跳到下一句和结束全文均通过串行播放器状态机执行。用户触发回听时，状态机先使正在加载但尚未发声的下一句失效，再固定本次操作的目标索引，避免句间竞态。`reader-view` 订阅播放器快照，只负责渲染和转发用户操作，不再自行推断句内状态。

### Web Speech 降级

Azure 或 R2 不可用时继续降级到现有 Web Speech 控制器。降级状态保留句级断点、倒计时和页面内重听，但不承诺锁屏后台连续播放或句内秒数恢复。页面显示“当前使用浏览器语音，锁屏后台播放可能受限”。

## Media Session

新增隔离的 Media Session 适配器，并对每项 action handler 单独做特性检测：

- `play`：继续全文朗读；
- `pause`：暂停并保存检查点；
- `previoustrack`：从当前句的上一句句首开始，结束后继续后文；
- `seekbackward`：浏览器提供该 action 时，从当前句句首重播，忽略系统传入的秒数，结束后继续后文；
- `nexttrack`：跳到下一句并继续；
- 支持时同步 `playbackState`、文章标题、作者和当前句摘要。

第一句是当前句时清除 `previoustrack` 处理器，文章最后一句是当前句时清除 `nexttrack` 处理器。浏览器不支持 Media Session 或某个 action 时不注册对应处理器，页面内控制保持完整可用。离开阅读器、结束全文或退出登录时清除处理器和元数据，避免控制旧会话。

## 播放检查点

### 数据模型

检查点包含：

- 用户标识；
- 文章 ID；
- 文章正文指纹，由正文内容确定且不受标题、作者等元数据变化影响；
- 当前句索引；
- 句内秒数；
- 保存时播放器状态；
- 保存时间。

本机检查点按用户和文章隔离存入 `localStorage`。D1 的 `article_progress` 新增非负的句内秒数字段，并与现有 `last_aloud_sentence_index` 一起由进度 API 读写。

倒计时是当前设备的播放会话状态，不同步到 D1。

### 保存时机

同步写入本机检查点：

- 开始全文朗读；
- 每次进入新句；
- 播放中按节流频率更新句内秒数；
- 暂停、恢复、上一句、本句和改变语速；
- `visibilitychange`、`pagehide` 和阅读器卸载；
- 倒计时触发暂停。

本机写入后，复用现有进度队列异步同步到 D1。队列仍按文章压缩位置快照，最新句索引和句内秒数必须作为一个不可拆分的快照保存。

### 恢复优先级

1. 同一文档仍存活且播放器仍持有当前文章时，亮屏后直接绑定内存中的播放器状态，不重新创建或重新开始音频。
2. 页面刷新或被系统回收后，优先读取正文指纹匹配的本机检查点。
3. 没有有效本机检查点时，使用 D1 的跨设备断点。

恢复音频源后等待媒体元数据可用，再将 `currentTime` 设为保存的句内秒数。若秒数超过音频时长，则从该句句首恢复。恢复只呈现“继续”，不得自动播放，以满足 Safari 和 Chrome 的用户手势要求。

文章正文变化或用户主动重置进度时，同时清除句索引、句内秒数和对应本机检查点。仅修改标题、作者、来源或笔记时保留检查点。

## 倒计时

新增独立的倒计时控制器，只维护启用状态和绝对截止时间。

可选时长为 10、20、30、60 分钟，并支持输入自定义正整数分钟。用户可以覆盖或取消已有倒计时。

倒计时校验发生在：

- 页面可见时的显示刷新定时器；
- 音频 `timeupdate`、`play`、`pause`、`ended` 和换句事件；
- `visibilitychange` 与 `pageshow`；
- 用户执行播放、恢复、上一句或本句前。

任何校验发现当前时间达到截止时间，都立即暂停当前音频、保留句内秒数、清除倒计时并发布“定时结束，已暂停”状态。继续播放不会自动重建已结束的倒计时。

倒计时与当前设备绑定，并保存在本机，使页面刷新后仍能判断是否已经到点。恢复时若截止时间已过，播放器保持暂停并清除倒计时。

## 页面交互

### 顶部朗读栏

保留播放/暂停、从头开始和语速，新增：

- “上一句”：当前实际发声句不是第一句时启用；
- “本句”：有当前实际发声句时启用；
- “定时”：打开倒计时面板；
- 剩余时间：启用倒计时后显示 `mm:ss`，超过一小时仍按总分钟显示。

点击“上一句”后，播放器从当前实际发声句的前一句句首开始，并按正常顺序继续后文。点击“本句”后，播放器将当前句 `currentTime` 设为零并立即播放，再继续后文。无论操作前处于播放还是暂停状态，两项操作都会开始播放。

例如第 6 句已经开始发声时，“上一句”从第 5 句开始并继续第 6、7 句，“本句”从第 6 句句首开始并继续第 7 句。若第 5 句已经结束而第 6 句尚未发声，当前句仍为第 5 句：“上一句”从第 4 句开始，“本句”重播第 5 句。

倒计时面板提供 10、20、30、60 分钟、自定义分钟、确认和取消倒计时。无效自定义值不提交，并提供就地错误提示。

### 移动端悬浮控制

顶部朗读栏离屏且没有词语或选区面板覆盖时，悬浮控制显示：

`上一句｜本句｜播放/暂停｜剩余时间或定时`

四项控制均保持至少 `44px` 的触控高度，并在 320px 宽度下使用紧凑文字和弹性宽度而不横向溢出。语速移出主操作序列，放入倒计时面板旁的次级设置区域。未启用倒计时时，第四项显示“定时”；启用后显示剩余时间并可重新打开面板。

当前全文朗读句继续高亮和自动跟随。普通模式下单击正文句子的现有单句点读保持不变。

## 状态与完成统计

- 上一句或本句回听不重复增加全文朗读完成次数，也不改变全文起始句。
- 跳到下一句会把当前句视为已离开，但不会伪造已完整播放覆盖率。
- 倒计时暂停属于可恢复的全文朗读会话，保存当前句和句内秒数。
- 只有自然到达文章末尾且满足现有完整朗读规则时，才清除断点并提交 `read_aloud_complete`。
- 用户主动从头开始时清除旧断点和句内秒数，再建立新的检查点。

## 错误处理

- 本机存储不可用：退回 D1 句级或句内断点，并保持朗读功能可用。
- 网络不可用：本机检查点继续更新，服务器同步进入现有重试队列。
- 检查点正文指纹不匹配、句索引越界或秒数无效：丢弃该检查点，不尝试猜测位置。
- 音频源加载失败：按现有策略降级到 Web Speech，并显示后台能力受限提示。
- 恢复设置 `currentTime` 失败：从保存句的句首继续，不能跳回文章开头。
- Media Session action 注册抛错：只跳过失败的 action，不影响其他 action 和页面控制。

## 测试与验收

### 自动测试

`tts-player` 单元测试覆盖：

- 整个全文会话复用同一个音频元素；
- 换句只替换音频源；
- 暂停与恢复保留句内秒数；
- 当前句只在实际发声后更新，预加载和缓冲不提前更新；
- 句中、句间和下一句已开始三种时序下，“上一句”与“本句”选择正确目标；
- 上一句或本句回听从目标句句首开始并继续后文；
- 倒计时到点在句中立即暂停；
- Web Speech 降级保持句级状态。

检查点与倒计时单元测试使用伪时钟和伪存储覆盖：

- 保存节流、关键事件立即保存和用户/文章隔离；
- 本机、内存与 D1 的恢复优先级；
- 正文指纹不匹配时失效，元数据修改时保留；
- 绝对截止时间、刷新恢复、到点清除和取消；
- 存储异常时的降级。

Media Session 测试覆盖每个 action、元数据和播放状态同步，以及不支持或单项注册失败的情况。

API 与数据库测试覆盖：

- 句内秒数迁移的约束和默认值；
- 进度 PATCH 的保存、读取和非法值拒绝；
- 文章正文编辑及重置进度时清除句内秒数；
- 旧客户端只提交句索引时仍兼容。

DOM 与样式测试覆盖：

- 顶部和悬浮“上一句”与“本句”，以及第一句时“上一句”禁用；
- 倒计时面板、预设、自定义、取消和剩余时间；
- 到点后的暂停状态与可访问状态通知；
- `320px`、`375px` 和横屏宽度下无溢出，主要触控目标不小于 `44px`；
- 键盘焦点、Escape 关闭面板及明暗主题。

### 用户手动验收

用户在真实 iPhone Safari 与 Android Chrome 上手动验收：

1. 开始全文朗读后锁屏，确认可以跨越多个句子继续播放。
2. 从锁屏控制暂停、继续和上一句；浏览器提供回退 action 时，再验证本句回听；锁屏界面未暴露某项 action 不视为页面功能失败。
3. 锁屏一段时间后亮屏，确认当前句和句内位置未丢失。
4. 刷新页面或让系统回收页面后重新打开，确认“继续”恢复到保存位置。
5. 设置短倒计时并在句中到点，确认立即暂停；分别覆盖亮屏和锁屏场景。
6. 在下一句已经开始后，分别点击“上一句”和“本句”，确认目标不同且回听后继续后文。
7. 在手机悬浮控制中连续使用上一句、本句、暂停、继续和定时，确认无误触且不遮挡文字选择。
8. 模拟云语音不可用，确认 Web Speech 降级提示与能力边界准确。

真机锁屏行为不能由 JSDOM 自动测试替代。用户手动验收通过是该功能完成的必要条件。

## 非目标

- 不开发原生 iOS/Android App 或原生壳。
- 不承诺操作系统冻结网页时仍能像原生后台任务一样准秒唤醒。
- 不生成整篇长音频、HLS 或 Media Source 播放列表。
- 不改变 Azure 声音、R2 逐句缓存键或月度字符预算规则。
- 不让倒计时跨设备同步。
- 不改变普通单击句子的单句点读行为。
