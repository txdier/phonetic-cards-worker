# 词间关系卡片内布局设计

## 目标

修复 PC 端词卡展开“词间关系”后，关系表单和已有关系行横向溢出并覆盖相邻词卡的问题，同时保持现有功能和移动端布局不变。

## 根因

PC 端词库使用三列词卡网格，单张词卡内部可用宽度约为 264px。关系表单当前使用四列网格，其中三列的最小宽度已经达到 350px，再加按钮和列间距后必然超过词卡宽度。

已有关系行同样使用带固定最小宽度的四列网格，因此保存关系后也存在相同的溢出风险。现有的单列保护规则只在浏览器视口不超过 640px 时生效，无法处理 PC 宽视口中的窄词卡。

## PC 端布局

关系表单在词卡内部改为两列三行：

```text
[搜索关联词] [搜索]
[关联词选择] [关系类型]
[备注      ] [添加关系]
```

两列均允许收缩到词卡可用宽度以内。输入框、选择框和按钮不得扩大词卡或覆盖相邻内容。

已有关系行改为两列两行：

```text
[目标词] [关系类型]
[备注  ] [删除]
```

第一列允许收缩和换行，第二列按内容宽度显示，从而保证长目标词、长备注和操作按钮都留在词卡边界内。

## 移动端布局

当视口宽度不超过 640px 时，继续使用现有的单列规则。关系表单的六个控件和已有关系行的四项内容按 DOM 顺序纵向排列，不改变交互顺序。

## 实施边界

- 仅修改 `public/styles.css` 中的关系表单和关系行网格规则。
- 不修改关系数据结构、API、表单字段、按钮文案或事件处理。
- 不改变词卡网格列数，也不让展开的词卡横跨整行。
- 保留现有 `≤640px` 单列断点。

## 验证

新增静态 CSS 回归断言，先证明当前关系表单和关系行仍使用会溢出的四列规则，再约束：

- PC 端关系表单使用两个可收缩列。
- PC 端已有关系行使用一个可收缩内容列和一个按内容宽度显示的操作列。
- 移动端仍将关系表单和已有关系行改为单列。

完成 CSS 修改后运行目标测试和完整测试套件，并在 PC 三列词卡布局中实际展开关系面板，确认面板、所有控件和已有关系内容均未越过词卡右边界。
